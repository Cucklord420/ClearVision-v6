# Repository agent instructions

Preserve inherited ClearVision source, license, notices, upstream attribution and theme behavior. Follow the owner's current [canonical guidebook](https://github.com/Cucklord420/Toe-Tickling/blob/main/GUIDEBOOK.md) within the applicable instruction hierarchy. Read and record the exact current revision before substantive work. Preserve all repository-specific safety and review requirements. A push to master may publish GitHub Pages; documentation authorization alone does not authorize a deployment.

## Explicit owner-directed additions — all repositories (11-24-2026)

When the owner explicitly directs an addition to a repository or project, execute the requested change rather than stopping at a plan, issue, or draft. For clearly requested, sanitized, non-executable documentation and instruction additions, the owner's instruction authorizes a direct update to an unprotected canonical default branch where actual permissions and repository rules permit it; no repeated approval is needed. Preserve all existing content and use a fresh expected-head, non-force fast-forward update, inspect concurrent work and verify the exact saved content. For protected branches, executable changes, or required checks/reviews, use the applicable review workflow and report any genuine blocker. Never bypass protections, validation, security, privacy, licensing, or authorization, and never infer permission for deployment, publication, purchases, destructive operations or unrelated changes.

## Mandatory final FMEA — all tasks (11-24-2026)

For EVERY task, subtask, project, repository, workflow, automation, decision, recommendation, change and deliverable, perform a proportionate Failure Mode and Effects Analysis (FMEA). Identify material failure modes, causes, effects, severity, occurrence/likelihood, detectability, existing controls, mitigation, verification evidence, rollback where applicable, residual risk and unresolved blockers. Prioritize severe consequences regardless of aggregate score; use qualitative or justified numeric ratings and mark unknowns rather than inventing evidence. Assess risks before consequential actions, reassess changed evidence, implement and verify authorized mitigations, and stop unsafe actions while continuing independent safe work.

At the very end of every delivered result include a **Final FMEA** section, concise for simple tasks and a structured risk register for complex or high-risk work. Preserve existing safety, privacy, review, source, test and notification requirements. If a run's existing contract requires silence, conduct the final FMEA internally and notify only when the existing material-risk or coverage criteria are met. Do not confuse analysis with verification or claim unverified completion.
